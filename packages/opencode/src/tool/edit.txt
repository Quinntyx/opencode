Performs exact string replacements in files. Supports two modes: hashline ref-based editing (primary) and oldString/newString (legacy fallback).

Hashline mode (preferred):
- Read returns canonical #HL refs (line#hash#anchor) plus a REV token. Copy refs exactly from the output.
- Use `ref` for single-line replacement, or `startRef`+`endRef` for multi-line range replacement, with `content` as the replacement text.
- Use `operations` array to batch multiple same-file edits in one call.
- Send `fileRev` from the Read output to detect stale-file edits early.
- Hashline prefixes inside `content` are stripped automatically.
- On hash mismatch, the error shows expected vs actual refs. Re-read the file and retry with fresh refs.

Legacy mode (oldString/newString):
- You must use your `Read` tool at least once in the conversation before editing.
- When editing text from Read tool output, ensure you preserve the exact indentation (tabs/spaces).
- The edit will FAIL if `oldString` is not found or found multiple times. Provide more surrounding context to make the match unique or use `replaceAll`.

General:
- ALWAYS prefer editing existing files in the codebase. NEVER write new files unless explicitly required.
- Only use emojis if the user explicitly requests it. Avoid adding emojis to files unless asked.
